# الرديّات والمحاورات والزوامل — الإصدار 9.0

منصة عربية متخصصة في **الرديّات الشعرية والمحاورات والزوامل**. حُوِّل المشروع من المنتدى السابق مع الحفاظ على نظام البث المباشر الأصلي (WebRTC + Socket.IO) ونظام الأعضاء والإدارة والتفاعل.

## أقسام الموقع

- **الرديّات:** نشر الردود الشعرية، الأبيات والتعليقات.
- **المحاورات:** مجالس للشعراء، بث مباشر متعدد المشاركين، طلب انضمام ودعوة الضيوف وتوزيع أدوار الكلام.
- **الزوامل:** نشر الزوامل نصًا وصورة وفيديو، مع مجالس للبث والأداء.
- تصفية الأقسام من الصفحة الرئيسية، إنشاء مجلس شعري وتحديد نوعه، والبحث في القصائد والمحتوى.

## الإمكانيات المحفوظة

- بث فيديو حي مباشر بين المضيف والضيوف مع مشاهدين ودردشة حية وتفاعل بالإعجاب.
- غرف صوتية، دور المتحدث، إدارة الدعوات، كتم المشاركين وإزالتهم.
- إضافة صورة أو مقطع فيديو إلى لوحة البث المباشر.
- تسجيل ودخول، ملفات شخصية، متابعة وتنبيهات، رسائل خاصة بعد الموافقة.
- نشر القصائد مع صور أو فيديو، التعليقات، الإعجاب، البلاغات والإشراف.
- لوحة الإدارة المنفصلة `/admin`، وسجل الإجراءات.

**ما أزيل من التطبيق العامل:** شريط الأخبار وRSS، دليل القنوات الإخبارية العالمية، تشغيل القنوات السياسية، وربط غرف جديدة بقنوات الأخبار. لا توجد استدعاءات تلقائية للأخبار بعد التحديث.

## التشغيل المحلي

المتطلبات: Node.js 20 أو أحدث، وقاعدة بيانات PostgreSQL متاحة.

1. انسخ `.env.example` إلى `.env` ثم ضع `DATABASE_URL` و`JWT_SECRET` قويًا.
2. نفّذ:

```bash
npm ci
npm run check
npm start
```

الروابط الافتراضية:

- الواجهة: http://localhost:3000/
- الإدارة: http://localhost:3000/admin
- الصحة: http://localhost:3000/api/health

يتولى الخادم تطبيق `schema.sql` تلقائيًا عند البدء، على قاعدة جديدة أو موجودة. ويمكن تشغيل `schema-updates.sql` يدويًا عند تحديث قواعد موجودة.

## ملاحظات الترحيل المهمة

- **خذ نسخة احتياطية من PostgreSQL قبل تشغيل الإصدار الجديد على قاعدة البيانات الحالية.**
- يُنشأ حقل `poetry_kind` وتُنشأ ثلاثة مجالس أساسية: `poetry-replies` و`poetry-dialogues` و`poetry-zawamil`.
- تُترك الغرف والمنشورات القديمة في قاعدة البيانات للاسترجاع، لكنها **مخفية وغير قابلة للوصول من واجهات المنصة الجديدة**. هذا يمنع عرض المحتوى السياسي القديم ولا يمس الحسابات أو الرسائل الخاصة.
- جداول القنوات الإخبارية التي قد توجد في قاعدة قديمة لا تُحذف آليًا حفاظًا على إمكانية الاستعادة؛ لا يستخدمها الموقع الجديد ولا ينشئها على قاعدة جديدة.
- لم تُنفّذ عملية نشر عام أو ترحيل لقاعدة بيانات حية ضمن هذا التغيير.

## حدود البث الحالي

يعتمد البث على WebRTC بنمط Mesh مع خادم STUN افتراضي. يمكن اختباره مع مجموعات صغيرة، لكنه **غير مُعدّ بعد لتحمل آلاف المشاهدين**؛ يتطلب العمل على نطاق إنتاجي إعداد TURN وSFU مثل mediasoup أو Janus. يجب اختبار الصوت والفيديو فعليًا من جهازين وشبكتين مختلفتين بعد إعداد HTTPS وبيئة PostgreSQL.

## فحوص ما قبل الإطلاق

- حساب جديد ثم تسجيل دخول، ونشر قصيدة بكل نوع من الأنواع الثلاثة.
- مراجعة ترتيب المجالس وتصفية القصائد في كل قسم.
- بث من جهاز، مشاهدة من جهاز آخر، قبول ضيف، كتمه، ثم إنهاء البث.
- غرف الصوت والدردشة والتعليقات والرسائل الخاصة.
- فتح `/admin` والتحقق من الصلاحيات ومراقبة البث.
- التحقق من أن `/api/political-news` و`/api/channels` يرجعان 404.
