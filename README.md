# ساحات سياسية — الإصدار 8.0

نسخة مطورة من المشروع المرفوع، مع بقاء واجهة المستخدم `/` ومركز الإدارة `/admin` منفصلين.

## الجديد في 8.0
- إصلاح مسار التعليقات من الواجهة وإضافة مربع تعليق مباشر أسفل كل منشور، مع Enter للإرسال وتحديث العداد فورًا.
- شريط عالمي للبثوث النشطة في أعلى الصفحة: الساحة، موضوع الحوار، اسم المضيف، عدد المشاركين والمشاهدين، والدخول المباشر للبث.
- تمييز المضيف والضيف المشارك باسم كامل وشارة دور، مع عرض أسماء المشاركين والمشاهدين.
- ملف شخصي: صورة، الاسم الظاهر، bio، تغيير كلمة المرور، ومنشورات المستخدم.
- متابعة المستخدمين، طلب مراسلة، قبول/رفض، إشعارات، قائمة متابعين ومتابَعين، ورسائل خاصة بعد القبول.
- موضوع الحوار (صورة/فيديو) تحت تحكم المضيف فقط؛ الفيديو يعمل Loop حتى يوقفه المضيف، مع تشغيل/إيقاف، كتم، إزالة واستبدال.
- المشاهد يستطيع طلب المشاركة، والمضيف يقبل أو يرفض ويستطيع دعوة مشاهد مباشرة أو استبدال ضيف.
- توزيع دور الكلام بين المشاركين بواسطة المضيف مع إبراز المتحدث الحالي.
- ترتيب الحوارات الحية وفق التفاعل (المشاهدون + الإعجابات + المشاركون) لإظهار الأبرز في الشريط.
- شريط أخبار سياسية عالمي من عدة RSS feeds، مع فلترة حسب المصدر واللغة. فشل مصدر واحد لا يوقف بقية المصادر.
- محدد لغة واسع للواجهة (45 locale) مع اتجاه RTL/LTR تلقائي. توجد حزم نصوص أساسية للعربية والإنجليزية والفرنسية والإسبانية والألمانية، وباقي اللغات تستخدم fallback حتى إضافة حزمة ترجمة كاملة.
- منع التنقل الداخلي الذي يقطع بث المضيف؛ البروفايل والرسائل والإشعارات تعمل كنوافذ داخل SPA. إعادة تحميل الصفحة/إغلاق التبويب يقطع WebRTC بطبيعته.

## البث
WebRTC الحالي Mesh/P2P ومناسب للتطوير والمجموعات الصغيرة. للإنتاج وعدد كبير من المشاهدين يجب استخدام TURN + SFU مثل LiveKit/mediasoup/Janus؛ وإلا سيزداد حمل رفع الفيديو على المضيف مع كل مشاهد.

## التشغيل
أنشئ `.env`:

```env
DATABASE_URL=postgresql://USER:PASSWORD@HOST:5432/DBNAME
JWT_SECRET=change-this-to-a-long-random-secret
PORT=3000
```

ثم:

```powershell
npm install
npm run check
npm start
```

- المستخدم: `http://localhost:PORT/`
- الإدارة: `http://localhost:PORT/admin`
- الصحة: `http://localhost:PORT/api/health`

## قاعدة البيانات
طبّق `schema.sql` على قاعدة جديدة، أو `schema-updates.sql` عند ترقية قاعدة موجودة. خذ نسخة احتياطية قبل أي migration.
